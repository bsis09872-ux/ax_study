## 1. 개발 환경 / 도구

### 가상환경 활성화와 `deactivate`
- 가상환경을 activate하면 터미널 앞에 `(환경이름)`이 붙고, `deactivate`라는 **함수가 임시로 생성**된다.
- `deactivate`를 실행하면 환경이 꺼지면서 그 함수도 같이 사라진다. 그래서 두 번 연속 실행하면 "인식되지 않습니다" 에러가 난다.
- 활성화 여부는 프롬프트 앞에 `(환경이름)`이 있는지로 확인한다.

### `VIRTUAL_ENV` 환경변수와 uv
- `VIRTUAL_ENV`는 "지금 활성화된 가상환경이 어디인지"를 담는 환경변수다.
- `uv`는 기본적으로 **현재 프로젝트 폴더의 `.venv`** 를 쓴다. 다른 프로젝트 환경이 켜져 있으면 경고를 띄우고 그 환경은 무시한다.
- 켜져 있는 환경에 굳이 설치하려면 `--active` 옵션을 쓴다 (보통은 필요 없다).
- `uv add`나 `uv run`만 쓴다면 activate를 안 해도 된다.

### Jupyter 커널 선택
- 노트북은 **오른쪽 위에서 고른 커널(파이썬 환경)** 으로 실행된다.
- 패키지를 설치한 `.venv`와 노트북 커널이 다르면 `ModuleNotFoundError`가 난다.

### 버전 고정 (Version Pinning)
- `uv add "ragas==0.x.x"`처럼 라이브러리 버전을 특정 값으로 묶어두는 것.
- 라이브러리가 업데이트되면서 내부 코드가 깨질 때 예전 호환 버전으로 고정해 해결한다.

### `utf-8-sig` 인코딩
- `df.to_csv(..., encoding="utf-8-sig")`
- 파일 맨 앞에 BOM 표시를 붙인 UTF-8이다. **엑셀에서 CSV 한글이 깨지지 않게** 할 때 쓴다.

## 2. 파이썬 문법 / 동작 원리

### `sys.modules`와 가짜 모듈 등록 (Monkey Patching)
```python
dummy = ModuleType("langchain_community.chat_models.vertexai")
dummy.ChatVertexAI = type("ChatVertexAI", (), {})
sys.modules["langchain_community.chat_models.vertexai"] = dummy
```
- `sys.modules`는 파이썬이 **이미 import한 모듈을 저장해 두는 사전**이다. import할 때 여기부터 확인한다.
- 여기에 빈 껍데기 모듈을 미리 넣어두면, 실제로 없는 모듈도 import에 성공한 것처럼 처리된다.
- 라이브러리가 **삭제된 모듈을 import해서 에러가 날 때 쓰는 임시방편**이다. 실제 기능은 없다.

### `type(이름, 부모들, 속성)`으로 클래스 만들기
- `type("ChatVertexAI", (), {})`는 `class ChatVertexAI: pass`와 같다.
- 클래스를 동적으로 만드는 방법이다.

### Deprecation Warning
- "이 기능은 곧 없어지니 새 방식으로 바꾸라"는 **경고**다. 에러가 아니므로 지금은 정상 동작한다.
- 버전을 올릴 때 깨질 수 있으니 안내된 새 방식을 기억해 둔다.
  - 예: `from ragas.metrics import ContextPrecision` → `from ragas.metrics.collections import ContextPrecision`
  - 예: `LangchainLLMWrapper` → `ragas.llms.llm_factory`

## 3. LLM / LangChain

### Vertex AI
- **Google Cloud의 AI 서비스**다. Gemini 같은 Google 모델을 API로 쓸 수 있다. "구글판 OpenAI API"라고 보면 된다.
- LangChain에서는 `ChatVertexAI`, `VertexAI` 클래스로 쓴다.
- 예전에는 `langchain_community` 안에 있었지만, 지금은 `langchain-google-vertexai`라는 별도 패키지로 옮겨갔다. 그래서 옛 경로로 import하는 라이브러리(예: ragas 일부 버전)에서 에러가 난다.

### `init_chat_model`의 인자 처리 방식
- 모르는 이름의 인자를 받아도 **바로 에러를 내지 않고** `model_kwargs`에 보관한다.
- 실제 API를 호출할 때 그 인자를 그대로 넘기고, **그 시점에야 에러가 난다**.
- 그래서 오타가 있어도 모델 생성 셀은 통과하고, 나중에 `invoke`나 `evaluate` 단계에서 에러가 터진다.

### `temperature`
- LLM 출력의 무작위성을 조절하는 값이다. `0`이면 가장 일관되고 결정적인 답을 낸다.
- 평가(채점)처럼 **매번 같은 기준이 필요할 때는 0으로 둔다**.
- **reasoning 계열 모델**(예: luna, o-시리즈)은 temperature 변경을 지원하지 않는 경우가 많다. 그래서 값을 넣으면 `BadRequestError`가 날 수 있다.

### `reasoning_effort`
- reasoning 모델이 답하기 전에 얼마나 "생각"할지 정하는 옵션이다 (`none`, `low`, `medium`, `high` 등).

## 4. RAG 평가 (RAGAS)

### LLM-as-a-Judge (LLM을 채점자로 쓰기)
- 사람이 아니라 **LLM이 RAG 결과를 채점**하는 방식이다.
- **자기 선호 편향 (Self-preference bias)**: LLM은 자기가 만든 스타일의 답을 더 후하게 평가하는 경향이 있다.
  - 그래서 **답변 생성 모델과 채점 모델을 다르게** 쓰면 다른 관점에서 평가하게 되어 더 객관적이다.
  - 비유하면 자기 시험지를 자기가 채점하지 않는 것과 같다.
- **채점 모델 고정**: 여러 RAG 설정(청크 크기, 리랭커 등)을 비교할 때는 채점자를 바꾸지 않아야 점수를 공정하게 비교할 수 있다.

### `EvaluationDataset`
- RAGAS가 요구하는 표준 평가 데이터 형식이다. DataFrame에서 `EvaluationDataset.from_pandas(df)`로 만든다.
- 주요 컬럼:
  - `user_input`: 질문
  - `retrieved_contexts`: 검색된 문서 리스트
  - `reference`: 모범 정답
  - `response`: 생성된 답변 (생성 평가 시)

### Context Precision / Context Recall
| 지표 | 질문 | 낮으면 |
|---|---|---|
| **Context Precision** (정밀도) | 검색된 문서 중 **쓸모 있는 게 위쪽에** 있나? | 관련 없는 문서가 섞이거나 상위에 옴 |
| **Context Recall** (재현율) | 정답에 필요한 정보가 검색 결과에 **다 들어있나**? | 필요한 정보가 빠짐 |

- 예: 관련 문서를 찾았지만 청킹 때문에 문장이 잘리면 **Precision은 높고 Recall은 낮게** 나온다.

### `LangchainLLMWrapper(..., bypass_temperature=True)`
- LangChain 모델을 RAGAS용 채점자로 감싸는 래퍼다.
- `bypass_temperature=True`는 RAGAS가 temperature 값을 **보내지 않게** 하는 옵션이다. temperature를 지원하지 않는 모델을 쓸 때 사용한다.

### 진행률 표시 `Evaluating: 6/6`의 의미
- **질문(샘플) 수 × 평가지표 수**다. 질문 3개 × 지표 2개 = 6.
- API 호출 횟수와는 다르다. 지표 하나가 내부에서 LLM을 여러 번 부를 수 있다.

### 검색 실패의 대표 원인
| 원인 | 증상 예시 | 해결 방향 |
|---|---|---|
| **메타데이터 필터링 미흡** | 2024년 질문에 2023년 문서가 검색됨 | 연도·학기 같은 메타데이터 필터 추가 |
| **청킹 분할 실패** | 문장이 "...(문맥 끊김)"으로 잘림 | 청크 크기나 overlap 조정, 문단 단위 분할 |
