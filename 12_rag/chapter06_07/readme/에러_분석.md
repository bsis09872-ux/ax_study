# 에러 분석 및 처리

> 실습 중 만난 에러와 해결 방법 기록. 새 에러는 맨 아래에 같은 형식으로 추가.
>
> **형식**: 상황 → 에러 메시지 → 원인 → 해결 → 교훈

---

## 에러 읽는 기본 습관
1. **맨 아래 줄**부터 본다. 에러 종류와 핵심 메시지가 거기 있다.
2. `Did you mean ...?` 같은 힌트가 있으면 대부분 오타다.
3. 위쪽 traceback에서 **내 코드 파일(Cell In[..])이 나오는 줄**을 찾는다.
4. 에러가 아래 셀로 번진 건지 확인한다. 앞 셀이 실패하면 뒤 셀은 `NameError`가 난다.

---

## 1. `deactivate` 용어가 인식되지 않습니다
- **상황**: PowerShell에서 `deactivate`를 두 번 연속 실행
- **원인**: 첫 번째 실행으로 이미 환경이 꺼졌고, 그때 `deactivate` 함수도 사라졌다.
- **해결**: 무시해도 된다. 프롬프트 앞에 `(환경이름)`이 없으면 이미 꺼진 상태다.
- **교훈**: 명령 실행 전후로 프롬프트 변화를 확인하자.

## 2. uv `VIRTUAL_ENV ... does not match the project environment path` 경고
- **상황**: chapter05 환경이 켜진 채로 chapter06_07 폴더에서 `uv add pydantic` 실행
- **원인**: 켜져 있는 환경(chapter05)과 현재 프로젝트 환경(`chapter06_07/.venv`)이 다르다.
- **해결**: 경고일 뿐이다. uv는 현재 프로젝트 `.venv`에 정상 설치했다. 신경 쓰이면 `deactivate` 후 해당 프로젝트 `.venv`를 활성화한다.
- **교훈**: 폴더를 옮기면 가상환경도 바꾸자. 노트북 커널도 해당 `.venv`로 맞춘다.

## 3. `ModuleNotFoundError: langchain_community...vertexai` (예방)
- **상황**: ragas import 시 라이브러리 내부에서 삭제된 vertexai 모듈을 import
- **원인**: LangChain 최신 버전에서 vertexai 모듈이 별도 패키지로 옮겨갔다.
- **해결**:
  - ① 노트북 첫 셀에서 `sys.modules`에 가짜 모듈을 등록한다 (→ 개념어 정리 "sys.modules" 참고).
  - ② 또는 호환되는 버전으로 고정한다.
- **교훈**: 라이브러리끼리 버전이 안 맞는 문제는 흔하다. 임시 패치인지 근본 해결인지 구분하자.

## 4. `SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?`
- **상황**: ragas 평가 셀
```python
metrics = [
    ContextPrecision(llm=evaluator_llm),
    ContextRecall(llm=evaluator_llm),

evaluation_result = evaluate(...)   # ← 리스트 안에 대입문
]
```
- **원인**: 리스트를 닫는 `]`가 맨 아래로 밀려났다. 대입문(`=`)이 리스트 안에 들어간 꼴이 됐다.
- **해결**: `]`를 metrics 바로 뒤로 옮긴다.
- **교훈**: SyntaxError가 가리키는 줄이 아니라 **그 바로 위 괄호**가 범인인 경우가 많다.

## 5. `TypeError: AsyncCompletions.create() got an unexpected keyword argument 'temparature'`
- **상황**: `init_chat_model(..., temparature=0)` 후 `evaluate()` 실행. 진행률 0/4에서 실패.
- **원인**: `temperature` 오타다. `init_chat_model`은 모르는 인자를 저장만 해뒀다가 API 호출 시점에 넘긴다. 그래서 모델 생성 때는 통과하고 실행 때 터진다.
- **해결**: `temperature=0`으로 고친다.
- **교훈**:
  - 에러가 **실제 원인보다 늦게** 터질 수 있다. 메시지의 인자 이름을 그대로 코드에서 검색하자.
  - 한 번 지적받은 오타는 수정했는지 꼭 다시 확인하자. 같은 오타로 두 번 실패했다.

## 6. `NameError: name 'rags_dataset' is not defined`
- **원인**: 변수명 오타 (`ragas_dataset`).
- **해결**: 위에서 정의한 이름과 똑같이 맞춘다.
- **교훈**: VS Code 자동완성(Tab)을 쓰면 이런 오타를 줄일 수 있다.

## 7. `NameError: name 'evaluation_result' is not defined` (연쇄 에러)
- **상황**: CSV 저장 셀에서 발생
- **원인**: 앞 셀(evaluate)이 실패해서 변수가 만들어지지 않았다.
- **해결**: **앞 셀 에러부터** 해결하고 순서대로 다시 실행한다.
- **교훈**: 아래 셀 에러는 위 셀 실패의 결과일 수 있다. 위에서부터 본다.

## 8. reasoning 모델에 temperature 지정 (주의사항)
- **상황**: `gpt-6-luna`처럼 temperature를 지원하지 않는 모델에 `temperature=0`을 지정
- **가능한 에러**: `openai.BadRequestError` (unsupported parameter)
- **해결**:
  - temperature가 필요하면 `gpt-4o-mini` 같은 일반 모델을 쓴다.
  - luna를 쓸 거면 temperature 줄을 빼고 `LangchainLLMWrapper(model, bypass_temperature=True)`를 쓴다.
- **참고**: 실습에서는 `temperature=0`과 `bypass_temperature=True`를 같이 써도 동작했다. 다만 설정이 서로 모순되니 하나로 정리하는 게 좋다.

## 9. 무시해도 되는 경고들
| 경고 | 의미 | 조치 |
|---|---|---|
| `TqdmWarning: IProgress not found` | 노트북 진행 표시줄 위젯이 없음 | 무시하거나 `uv add ipywidgets` |
| `DeprecationWarning: ... ragas.metrics ...` | import 경로가 곧 바뀜 | 지금은 동작함. 새 경로 기억해두기 |
| `DeprecationWarning: LangchainLLMWrapper` | 래퍼가 곧 없어짐 | 추후 `llm_factory`로 바꾸기 |

> **Warning과 Error 구분**: Warning은 실행이 계속되고, Error는 실행이 멈춘다.
